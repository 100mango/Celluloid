# Independent runtime continuation while renderer qualification remains red

The early original-UIKit 2x/3x comparison is unchanged. Its actual exit status and
strict full/component assertions remain visible failures. A separate verifier can
admit independent functional coverage only after both intended consumers executed
exactly once, on distinct actual displays, with the same built/installed app and
exact source-bound Mac fixture. It verifies raw assertions, finalized device/test
summaries, bounded process timing, exact base/sticker output, and successful owned
simulator cleanup plus observed disappearance. Missing, contradictory, structural,
permission, process or unexpected assertion failures stop continuation. Only the exact already-observed Celluloid file-open console diagnostic is retained
verbatim with a count as unclassified; it is not by itself an authoritative
XCTest/process failure for scheduling unrelated functional tests. No harmlessness
or framework/cache origin is inferred. It cannot excuse an assertion, crash,
timeout, inconsistent process outcome, missing summary or cleanup failure, and
all final rendering/release acceptance remains blocked.

The only failure category admitted for diagnostic continuation is the existing
full/bubble/all-artwork strict channel comparison. This does not qualify those
pixels, typography, geometry, Photos preservation, or a production release. The
original UIKit production fingerprint and consumer-test source are pinned. Any
future diagnostic instrumentation requires explicit review and a new test pin.

`continuation_safe` and `strict_pixel_passed` are separate facts. The workflow
preserves the early step's failure, does not use `continue-on-error`, and explicitly
freezes unsigned archives pending an independently reviewed replacement renderer
contract and actual Photos-host preservation. Full runtime jobs retain their own
required tests and can still fail; none inherit acceptance from continuation.
