## Isolation and data contract

- `CelluloidNative.xcodeproj` is independently generated by `Scripts/generate_native_project.py`. The shipping iOS project and sources are untouched.
- Native Mac and visionOS use `FileDocument`/`DocumentGroup`, one editable value per window, with explicit Undo/Redo and source-preserving document packages.
- A `.celluloid` package contains `recipe.json` plus UUID-derived `.image` filenames. Format `Celluloid.Document`, version 1 uses finite normalized top-left coordinates. It does not read or write Photos adjustment `Mango.CelluloidPhotoExtension` version `1.0`.
- Missing/unknown document versions, duplicate source/layer identities, unbounded geometry, unexpected/missing package children and source dimension mismatches fail explicitly. Imports are all-or-nothing. Up to four originals, each at most50 megapixels and together at most64 MB, are retained. Undo keeps at most20 groups and a conservative128 MB distinct-original budget; older undo history is visibly cleared when a new import would exceed it. Current and immediately previous imports remain undoable.
- All original 23 stickers, 10 bubbles, text-area JSON, 25 collage templates and LICENSE are copied byte-for-byte into a versioned local rendering package. `resource-provenance.json` identifies their original locations and hashes.
- Filter IDs retain their historical meaning, notably `Fade` → `CIPhotoEffectInstant`. A missing filter throws rather than silently returning unfiltered output. A successfully executed face detector finding no face legitimately preserves the image.
- Native bubble rendering uses Core Text and normalized font sizes. This is not a claim of pixel or typography equivalence to UIKit; that comparison remains a gate before shared-code wiring or layered native Photos-extension support. The isolated filter-only extension compiles, while its real Photos-host save/reopen/Revert path remains unproved.

## Static-photo contract

Native documents retain imported original file bytes. Rendering is a static-image, sRGB, 8-bit SDR workflow; PNG preserves alpha and JPEG composites onto white. No claim is made for editable HDR gain maps, Live Photo motion/audio, depth, RAW development controls, animation, or retention of camera metadata in finished exports. Opening a source does not modify its Photos-library asset. The separate iOS Photos-host non-destructive workflow remains on its original implementation.

Image-format tests use Apple ImageIO to encode synthetic PNG/JPEG/HEIC/HEIF when the runner advertises that encoder, then compare oriented output with an independent ImageIO thumbnail transform oracle. Missing HEIC/HEIF encoders are explicit unverified coverage, not product passes.

The 50,000,000-pixel native limit deliberately accepts the common8064×6048 (48,771,072) geometry. Encoded originals remain bounded to64 MB combined. RAW/ProRAW and multi-frame images are rejected with an explicit explanation; no RAW decoder or embedded-preview behavior is being claimed. The practical memory gate retains its original1.5 GB peak and256 MB repeated-growth limits.

## Legacy collage distinction

The original iOS `CollageContentView` draws a3-point black CAShapeLayer stroke and begins with the model’s zero/top-left scroll offset. New native recipes deliberately use a normalized centered focal point by default and do not add that legacy stroke. Template/source-color/order tests validate the new renderer’s requested composition; they do **not** establish legacy collage pixel equivalence. UIKit collage remains untouched and is not routed through this renderer. Native bubble typography also remains a separate equivalence gate before any Photos editing extension or original-iOS wiring.
